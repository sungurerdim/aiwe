# Working in this repository

aiwe turns a goal into verified, merged code through small units, each run by a role-specific agent. This file
holds no state and repeats no rule: it says where each fact lives. Reply to the owner in Turkish; write everything
committed to this repository in English (DR-18).

## 1. At session start

1. Read [docs/standards.md](docs/standards.md), the rule registry (DSH does not resolve `@`, so open it by path).
2. Read the four project records at the repository root, in this order: `TODO.md` (every open work item, in order),
   `STATUS.md` (current state; its hand-kept "Broken" and "Live configuration" stay), `DECISIONS.md` (index of
   SPEC §16, only when a choice is involved) and `ARCHIVE.md` (closed items). `TODO.md`, `ARCHIVE.md` and
   `DECISIONS.md` are generated and not committed (L41); regenerate all four with
   `go run ./internal/cmd/records --write all` before reading, and after closing an issue. This interim tool is
   deleted when `aiwe item list`, `ready`, `archive` and `aiwe status` land (L41, K32).
3. Run `python ../aiwe-wt/runs/order.py --limit 20 --why`: the derived work order.
4. Run `python ../aiwe-wt/runs/status.py --needs-lead`: the unit states.
5. Read the owner's current preferences and first work in `STATUS.md` "Live configuration"; they bind every session.
6. Read `../aiwe-wt/runs/lead-tools/pending-dispatch.md`: the next step of every unit in flight, newest section last.
7. An external agent then reads `../aiwe-wt/HANDOFF.md`, the contract of the bridge.

## 3. Project rules

**Checks.** An agent never runs the gate, a unit verify, or a test, lint or build command itself (DR-8, SPEC-contracts §9.4). It
asks for its unit verify through `aiwe verify`; the engine runs it and records the result. Until `aiwe verify`
exists, the lead session runs each verify once and records it. The full gate runs only in CI, once per batch
pull request (SPEC §7.8, §12.2). Locally run only the step a change touches,
`go run ./cmd/aiwe gates gate --repo . --step <id>`; the full gate runs locally only as a release rehearsal. The CI
gate must exit 0 before a batch lands.

**Red lines.** Each line names the rule; the rule text is in `docs/standards.md`.

- aiwe is built with aiwe (DR-23). Until M-Skeleton closes, only the lead session and its role-specific agents work, by
  hand, under L5. After M-Skeleton closes, a unit worked outside aiwe is a defect and is recorded as one; CI flags a
  `main` commit that closes a unit and has no `Run-Id` trailer (Q17).
- The work store is the single source of truth for work: every piece of work is a typed item before it starts (DR-20, O31,
  SPEC-contracts §8.4); until the cutover (L61), that item is a GitHub issue written by `aiwe-wt/issue.py`. Commit trailers are in SPEC §12.3 (R5), written by the engine. A bridge
  unit has no remote: it closes with its evidence file until #269 removes the bridge (SPEC §6.3).
- Every diff counts from the run's base commit (DR-9).
- Commit only on your run branch; no push, merge, issue close or tracker write (DR-13).
- A unit stays inside its declared file set (DR-7, DR-9).
- Tests are never weakened, skipped or mocked away (DR-12).
- Absence is not evidence; unmeasured is `unknown`, never `0` (DR-6). Tool output is not evidence by itself: name the
  work item, the SHA and the run.
- No machine-specific path and no product name outside its one constant (DR-17); no recursive removal outside its one
  owner (DR-11).
- No new third-party dependency outside the allow-list without an owner decision (DR-21).
- Source, docs and commit messages are in English (DR-18); commit messages follow SPEC §12.3. A breaking marker needs
  the owner's approval.
- Every element must be necessary (DR-22).

**Lead workflow until `aiwe verify` lands.** The steps the engine will take over; each names its source.

- Fix before check (L79, #617): in the unit clone, run `gofmt -w` on the unit's Go files and
  `golangci-lint run --fix` on its package first; commit what they change as a `style` commit. Only what remains is
  a finding. Never pass `--unsafe-fixes`.
- Verify, one command at a time through the machine slot queue
  (`python3 ~/.agents/araclar/agir-is-kuyrugu.py -- <command>`): the unit's narrow `go test ./internal/<pkg>/ -run
  '<tests of the change>' -count=1`, `go vet ./internal/<pkg>/`, `go run ./cmd/aiwe gates gate --repo . --step lint`
  (read its `lint:` line; the gate exits 1 as `incomplete` when one step runs) and
  `go run ./internal/cmd/repocheck all --repo .`. Write each output to the evidence folder (section 2) with the SHA.
- A source-rules finding is fixed at its cause: build the value at run time or from its one constant. Splitting a
  string to slip past a rule is a defect.
- Land a unit by `git cherry-pick` onto local `main`. Cherry-pick skips the commit-msg hook, so run
  `go run ./internal/cmd/repocheck commit-msg --repo .` on every landed message. This repository refuses a `Refs`
  line; the header is at most 50 characters, a body line at most 72, and a `Closes` commit carries
  `Effect: <before> → <after>` on one line. Reword with `git cherry-pick -n` and `git commit -F <explicit path>`.
- Push, CI and release wait for a batch (`STATUS.md` "Live configuration").
- Write an issue only with `aiwe-wt/issue.py ac|guncelle`, from a JSON body file (SPEC-contracts §8.4). The body needs
  a `key`. A path not yet on `main` goes in both `scope.in` and `scope.new`. An overlap refusal (`#N scope-in`,
  `out-in`) is answered with a factual `--distinct N:<reason>` or a narrower scope, never by dropping a real path.
  `--ust <N>` links the parent.

**What the global rules leave to this project.** `~/.agents/AGENTS.md` binds here; it names these as project settings:

- Item tool and template: `aiwe item` is the target (O31); `aiwe-wt/issue.py` stays the only writer until the cutover (L61), writing the English JSON record of SPEC-contracts §8.4.
- Commit trailers: SPEC §12.3 (R5). Until the cutover (L61), a unit commit carries the one `Closes <owner>/<repo>#N` the
  engine writes and a non-unit commit carries no issue trailer. After it, a commit names its item: `Closes: <item-id>`
  in a unit commit, `Refs: <item-id>` in another commit of an item (L33). The effect goes in the body, never in a trailer.
- Language of work items and commits: English (DR-18); only replies to the owner are Turkish.
- Narrow test command: none for an agent. One global rule does not apply: an agent runs no test, narrow or full; it
  asks for its verify (Checks above, DR-8).
- Push: an external agent never pushes, merges or closes (DR-13, `aiwe-wt/HANDOFF.md`).

**Known traps.** Tool facts that cost a run, kept here until the bridge retires (R8).

- Host hooks enforce these only in the host that runs them (section 4); follow them by hand elsewhere: no `--no-verify`, no
  `git filter-branch`, no `git reset --hard`, no `git clean -f`; commit messages come from a file
  (`git commit -F <explicit path>`). To undo work in a tree, use `git restore --staged --worktree .`; to reword a
  local commit, use a new branch, `git cherry-pick -n` and `git commit -F <explicit path>`.
- A clone's pre-commit hook counts DR-11 from `.git/aiwe-base`, else from the merge base with `origin/main`. A clone
  that works on top of the batch and has no `aiwe-base` sets `git update-ref refs/remotes/origin/main <batch tip>`.
- Turkish text never enters git or `gh` argv, a commit message or a tracked file (DR-18).
- A lint step that builds `custom-gcl` from the upstream clone loaded no packages on the measured host; the gate runs
  the tools-module golangci-lint instead (SPEC §5.17, §12.2, #365).
- Read a process's command line before killing it. `pipe.py`, `ext.py` and `pytest` all belong to some unit's run, and a
  kill by process name takes a neighbour's work with it; name the pid and the unit it serves.
- One heavy integration at a time. `queue.sh` and `ship.sh` hold `.batch.lock` because two of them collide in the
  process tree, not out of caution: a second queue is refused with a reason, and that refusal is correct. A killed queue
  leaves the lock behind (its exit trap never runs): with no live `queue.sh` or `ship.sh`, `rmdir aiwe-wt/.batch.lock`.
- A session that drives units keeps its working discipline in `aiwe-wt/evidence/mcp-path.md` (parallel width, gate
  batching, evidence before a close). It is a pointer: the rules stay in the SPEC and the registry.

**Host tools (dsh).** `dsh-github` (`gh_*`, read-only; `issue_*` and `pr_*` are lead-only), `dsh-taskboard` and
`dsh-mcp-panel` add tools and change no rule; where one is absent, `gh` and the tracker API are the fallback. DR-13 and
DR-20 stand: `todo_write` and `taskboard_*` are scratch state for one session, never a tracker.

## 4. Lead-host only

- Hooks in `~/.claude/hooks/` run only in the lead host; the Known traps above list what they enforce.
- RTK (`~/.claude/RTK.md`, imported by `~/.claude/CLAUDE.md`) is a token proxy; ignore it in other hosts.
- Memory: `~/.claude/projects/D--GitHub-aiwe/memory/` (`MEMORY.md` indexes it). It holds host working notes only; a
  preference lives in `STATUS.md` "Live configuration" and a rule or decision in SPEC §16.
