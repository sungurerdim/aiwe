# Standards registry

The one registry of aiwe's rules (#314 K41): every design rule DR-1…DR-23 and every standard of
SPEC §3.1. SPEC §3 mirrors the rows below; a difference in id, statement or enforcement is a `repo/registry`
finding. A wrong `rev` and a duplicated id are not yet findings (planned #423).

A row: **id** · **statement** (the text SPEC carries) · **enforcement** (a check id, `test` plus a
path relative to `internal/` and one test function, `judgement:<role>`, or a named CI or release
step written `planned: release step <name>` or `planned: CI job <name>`; `planned #N` is the issue
for an enforcement the row does not have yet) · **fix** (the one line an agent reads when the row is
red) · **milestone** (the roadmap goal of §13 whose conformance unit this row parents, #314 K36) ·
**rev** (the short hash of the row's statement and enforcement, the first 8 hex of sha256(statement
+ LF + enforcement); every row below carries it).
